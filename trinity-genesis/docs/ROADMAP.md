# Trinity & Ask_Pete Roadmap

This document outlines the strategic development path for the Trinity AI Agent System and the Ask_Pete Initiative. The goal is to build a scalable, autonomous authoring tool that evolves from text-based interactions to fully immersive 3D simulations.

## Phase 1: Text-Based Scale (Current)

**Focus:** Foundation, Knowledge Ingestion, and Basic Autonomy.

- [x] **Core Agent Architecture**: Rust-based `trinity-brain` and `trinity-body`.
- [x] **Memory System**: Ingestion of Ask_Pete research documents (`docs/ask_pete_memory`).
- [ ] **CLI Interactions**: Robust command-line interface for tasks and queries.
- [ ] **Data Mining**: Continuous extraction of knowledge from new research artifacts.

## Phase 2: 2D Interactive (Next)

**Focus:** Visualization, "Iron Road" Physics, and Bevy UI.

- [ ] **Bevy UI Integration**: Replace/augment CLI with a graphical "Authoring Tool" interface.
- [ ] **Iron Road Visualization**: 2D graph representation of the "Cognitive Railway".
- [ ] **Interactive Graphs**: Drag-and-drop nodes for game design and logic flow.
- [ ] **Map Editor**: Basic 2D tile branding for the Ask_Pete educational zones.

## Phase 3: 3D Simulation (Future)

**Focus:** Immersion, Real-Time Simulation, and GPS Integration.

- [ ] **3D Bevy World**: Full 3D rendering of the learning environment.
- [ ] **Avatar Embodiment**: 3D character models for the AI agent (Trinity).
- [ ] **GPS/Geolocation**: Integration for "Physical AI" campus scaling at Purdue.
- [ ] **VR/AR Bridges**: Experimental interfaces for immersive learning.

## Development Principles

1. **Trinity as the Engine**: Trinity is the toolbuilder and the intelligence.
2. **Ask_Pete as the Content**: Ask_Pete is the curriculum and the application context.
3. **Rust-First**: Performance and safety via Rust and Bevy.
4. **Autonomy**: The system should increasingly write its own code and content.
