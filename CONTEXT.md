## 🏗️ Master Architecture: The VaaM Engine

The "Vocabulary-as-a-Mechanic" (VaaM) engine is the core innovation. It models Cognitive Load Theory using game physics.

### 1. The Physics of Cognition (Iron Road)

Defined in `crates/iron-road-physics`.

- **Mass (Intrinsic Load)**: The inherent difficulty of a concept (1-100). "Hard words are heavy."
- **Friction (Extraneous Load)**: The drag caused by confusion or poor design. "Bad UI is sticky."
- **Steam (Germane Load)**: The kinetic energy generated by successful understanding. "Movement is learning."
- **Combustion (Attention)**: Burning "Coal" (Motivation) to generate Steam.

**The Equation**: `Velocity = (Power * Steam_Efficiency) / (Mass * Friction)`

### 2. The Data Substrate (Weigh Station Pipeline)

Before a word enters the game, it must be "weighed" by AI.

1. **Ingestion**: Designer submits raw text.
2. **Weighing (Llama 4 Scout)**: LLM analyzes the word for Mass, Tier (Basic/Academic/Hazardous), and Semantic Tags based on curriculum context.
3. **Storage**: Persisted in `vocabulary_bank` (PostgreSQL/SQLite).
4. **Instantiation**: Loaded into Bevy as a `VocabularyItem` entity.

### 3. The Runtime Engine (Bevy ECS)

Implemented in `crates/trinity-client`.

#### **Atoms of Language (Components)**

- `VocabularyItem`: The physical entity.
- `CognitiveWeight`: The mass component.
- `SemanticSocket`: The receptor (puzzle) that requires specific tags to solve.
- `MasteryStatus`: Tracks usage ("Rule of Three": Acquisition, Application, Reinforcement).

#### **The Interaction Loop**

1. **Drag & Drop**: User moves a `VocabularyItem` to a `SemanticSocket`.
2. **Tag Verification**: System checks if tags match (e.g., "Time" tag fits "Crumbling Bridge" socket).
3. **Logistics Check**: `d20 + Stats (Intelligence) - Friction >= Difficulty Class (DC)`.
4. **Resolution**:
    - **Success**: Convert Coal -> Steam. Update `MasteryStatus`.
    - **Failure**: Increase Friction (Confusion).
